# Consilience

Independent looks at the same thing, brought to one cloth. The product is a mental model someone can work from.

A named frame is worn for the answer. Open that bruh reference and keep every path. An unnamed question stays in plain prose.

Do not edit the tree to explain it.

## Procedure

1. **Question.** One sentence: what they want understood, and the tree it lives in. If the scope is ambiguous, state the reading you are taking and continue.

2. **Looks.** Count the boundaries the question actually crosses. A skill and its recipe, a host and a module, the vault and `nix-os`, two hosts. Zero boundaries is one look. One boundary is two looks. Stop at two. Name each angle before anyone reads.

3. **Explore.** You may write the answer from files already in hand. When the read is the work, send a readonly local explorer. Two looks means two explorers. They do not see each other. The prompt is [references/brief.md](references/brief.md). Launch with the read-only shape in `cli-coding`'s Pi leaf. Do not add `edit` or `write`. One stream means the second starts after the first returns.

4. **Weave.** Keep a disagreement as two findings until you have checked the file yourself. A missing look stays a gap. Do not invent the side you did not see.

## Report

Drop a section that the question does not need.

### Overview

What it is, what it does, and why it is there. A reader can stop here.

### Where it lives

The files someone would open first.

### How it works

The flow in prose. Name the file and the function. A diagram only when the prose cannot carry the handoff.

### Gotchas

The surprise, the pitfall, the gap. Skip the section when there is nothing.

### Looks

Who looked, at which angle, or that a look was absent.
